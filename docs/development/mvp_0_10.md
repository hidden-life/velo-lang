# Velo MVP 0.10 status
MVP 0.10 focuses on annotation foundation and annotation-based HTTP routing.

MVP 0.9 introduced a working HTTP server mode with explicit routing helpers.

MVP 0.10 keeps those helpers working and starts adding declarative route metadata.

## Roadmap
```text
0.10.1      lexer/parser/AST support for function annotations
0.10.2      semantic validation for annotations
0.10.3      IR/module metadata propagation
0.10.4      HTTP route annotation validation
0.10.5      serve mode annotation route dispatch
0.10.6      docs/examples/release checklist
```

## Current step
```text
0.10.4      HTTP route annotation validation
```

## Annotation syntax
Initial annotation syntax is supported before function declarations:
```velo
@http::get("/health")
fn health(req: http_request): http_response {
    return http::text_response(200, "OK");
}
```

Supported annotation forms:
```text
@name
@module::name
@name("string")
@name("string", true, 123)
```

Supported annotation argument literals:
```text
string
bool
int
```

## 0.10.1 scope
Implemented:
- `@` lexer token
- function annotation AST nodes
- parser support for annotations before `fn`
- AST printer support
- parser diagnostics for annotations before non-function declarations
- lexer/parser/printer tests
- documentation

Not implemented yet:
- semantic validation of annotation names
- HTTP route interpretation
- route table generation
- annotation metadata in IR
- annotation metadata in bytecode
- struct/field/parameter annotations

## 0.10.2 semantic annotation validation
MVP 0.10.2 adds generic semantic validation for function annotations.

The semantic analyzer validates:
- annotation names are present
- annotation names use `@name` or `@module::name`
- qualified annotation module names are visible through `use`
- duplicate annotations on the same function are rejected
- annotation metadata remains independent from HTTP routing

Accepted examples:
```velo
@auth(true)
fn main(): int {
    return 0;
}
```

```velo
use std::http;

@http::get("/health")
fn handle(req: http_request): http_response {
    return http::text_response(200, "OK");
}
```

```velo
use std::http as web;

@web::get("/health")
fn handle(req: http_request): http_response {
    return web::text_response(200, "OK");
}
```

Rejected examples:
```velo
@http::get("/health")
fn main(): int {
    return 0;
}
```

The qualified annotation requires a visible import:
```velo
use std::http;
```

```velo
@std::http::get("/health")
fn main(): int {
    return 0;
}
```

Deep annotation names are rejected in MVP 0.10.2. Use `@http::get(...)`, not 
`@std::http::get(...)`.

HTTP-specific validation is intentionally deferred to later MVP 0.10 steps.

## 0.10.3 IR annotation metadata
MVP 0.10.3 propagates function annotations from AST into IR.

The lowering pipeline now preserves function annotation metadata:
```text
AST::FunctionDeclaration.annotations
    ↓
IR::Function.annotations
```

The IR has its own annotation metadata structs:
```text
IR::Annotation
IR::AnnotationArgument
IR::AnnotationArgumentKind
```

The IR does not store AST annotation objects directly.

This keeps IR independent from parser/source-level AST ownership.

Qualified annotation names are normalized during lowering.

Example source:
```velo
use std::http as web;

@web::get("/health")
fn health(req: http_request): http_response {
    return web::text_response(200, "OK");
}
```

IR metadata:
```text
http::get("/health")
```

This allows future HTTP route dispatch to work with canonical module names instead
of local import aliases.

Not implemented in this step:
- HTTP route table construction
- route dispatch
- HTTP-specific annotation validation
- bytecode annotation metadata

## 0.10.4 HTTP route annotation validation
MVP 0.10.4 adds HTTP-specific semantic validation for route annotations.

Supported annotations:
```velo
@http::get("/path")
@http::post("/path")
```

Import aliases are supported:
```velo
use std::http as web;

@web::get("/health")
fn health(req: http_request): http_response {
    return web::text_response(200, "OK");
}
```

Validation rules:
- route annotation must have exactly one argument
- route argument must be a string literal
- route path must start with `/`
- route handler must have exactly one parameter
- route handler parameter must be `http_request`
- route handler return type must be `http_response`
- duplicate method/path routes are rejected
- multiple HTTP route annotations on the same function are rejected

This step does not add serve dispatch by annotations.

The server still uses the conventional `handle(req)` entry point until MVP 0.10.5.
